# Apps Script Bridge — живая приёмка 2026-08-23

## Итог

Apps Script Bridge проверен на отдельной временной Google-книге и искусственных
финансовых данных. Подтверждены двусторонняя синхронизация, обработка конфликтов,
идемпотентность, HMAC-защита, пауза синхронизации и восстановление очереди после
DNS-ошибки и HTTP 503 без потери или повторного применения бизнес-события.

- Проверялся код ветки `codex/finspace-ui-integration` на контрольной точке
  `0e7db7a` с локальными незакоммиченными исправлениями.
- Реальные финансовые сведения не использовались.
- HMAC secret, токены, cookie, заголовки подписи и содержимое `.env` в отчёт не
  включены.
- Commit, push, merge и deploy не выполнялись.

## Проверенные сценарии

### Finspace → Google Sheets

- Первичная выгрузка доставила шесть событий и завершилась ACK без остатка в
  outbox.
- Созданная в Finspace операция появилась в книге со статусом `SYNCED` и
  согласованной version.
- Повторный pull при пустой очереди не создавал дубли.

### Google Sheets → Finspace

- Пользовательское изменение строки перевело её в `DIRTY`.
- Ручной push обработал одну запись без остатка в локальной очереди.
- Backend сохранил изменение, увеличил version, после ответа строка стала
  `SYNCED`.
- Повторная доставка одного event ID была распознана как `duplicate`; версия
  финансовой операции увеличилась только один раз.
- Для реальной строки счёта DNS-ошибка оставила тот же event ID и статус
  `PENDING`; после восстановления URL повторная отправка изменила backend ровно
  один раз (`version` 3 → 4) и очистила очередь.
- Для реальной строки категории HTTP 503 дал тот же результат: event ID
  сохранился, backend остался на `version` 3, а успешный retry завершился
  `SYNCED` с `version` 4.

### Account и category lifecycle

- Через реальные API выполнены create → archive/delete → restore для временных
  account и category.
- На каждом шаге проверены HTTP 200, последовательное увеличение `version` и
  непустой `updated_at`; `INTERNAL_ERROR` не воспроизведён.
- Первопричина прежнего ложного `INTERNAL_ERROR`: FastAPI сериализовал ORM-объект
  после `commit`, а при `expire_on_commit=True` его поля уже требовали
  асинхронной перезагрузки. Route теперь формирует Pydantic DTO до commit и
  возвращает отделённые скалярные данные.

### Конфликты

Созданы три независимых stale-version конфликта. Для каждого подтверждены
снимки значений БД и Sheets, версии, источник и открытый статус. Проверены все
варианты разрешения:

- `keep_database`;
- `keep_sheet`;
- `manual_merge`.

После разрешения открытых конфликтов не осталось. Наблюдаемое ограничение:
последующий pull может вернуть строку книги к каноническому значению БД и
пометить её `SYNCED`, при этом исходный conflict snapshot продолжает храниться
в истории. Интерфейс должен объяснять это как историю разрешения, а не как
текущее состояние строки.

### Отрицательные проверки

| Сценарий | Ожидаемый результат |
|---|---|
| Неверная подпись | HTTP 401 `APPS_SCRIPT_SIGNATURE_INVALID` |
| Просроченный timestamp | HTTP 401 `APPS_SCRIPT_REQUEST_EXPIRED` |
| Повтор nonce | HTTP 409 `APPS_SCRIPT_REPLAY_DETECTED` |
| Чужой spreadsheet ID | HTTP 403 `WORKSPACE_ACCESS_DENIED` |
| ACK неизвестного события | HTTP 403 `WORKSPACE_ACCESS_DENIED` |
| Push при paused binding | HTTP 409 `GOOGLE_SYNC_PAUSED` |

В Apps Script пауза отображалась сообщением «Синхронизация приостановлена».

### Недоступность backend

Проверены два независимых live-сценария из настоящего привязанного Apps Script:

| Сбой | Состояние до восстановления | Результат retry |
|---|---|---|
| DNS: несуществующий HTTPS-host | `PENDING`, event ID и payload сохранены, backend `version` не изменён | `SYNCED`, очередь 0, backend `version` увеличен ровно один раз |
| HTTP 503: отдельный временный responder | `PENDING`, тот же event ID, видимая `BRIDGE_HTTP_ERROR`, backend `version` не изменён | `SYNCED`, очередь 0, ошибка очищена, backend `version` увеличен ровно один раз |

После финального pull статус показал: backend outbox — 0, локальная очередь — 0,
последняя ошибка — отсутствует. Предыдущее наблюдение о возможной потере локальной
очереди устранено: event ID дополнительно хранится в note статусной ячейки,
очередь восстанавливается по `DIRTY`/`PENDING`, а элемент удаляется только после
валидного подтверждения конкретного события.

## Исправление setup

`setupFinspace()` больше не вызывает построение меню через
`SpreadsheetApp.getUi()`. Это исключает ошибку `Cannot call
SpreadsheetApp.getUi() from this context` при запуске функции из редактора.
Меню создаётся `onOpen` после возврата в книгу и перезагрузки страницы.

## Очистка

- До удаления подтверждены backend outbox — 0, локальная очередь — 0,
  открытые конфликты — 0 и отсутствие последней ошибки.
- Удалены три installable trigger; Document Properties и локальная очередь
  очищены через меню книги.
- Apps Script binding удалён: последующий GET вернул HTTP 404.
- Тестовые account и category архивированы на `version` 5; последующие GET
  вернули HTTP 404. Новых pending outbox и конфликтов не появилось.
- Временная Google-книга вместе с привязанным Apps Script-проектом удалена без
  возможности восстановления.
- Остановлены и удалены только четыре E2E-контейнера; volumes и образы не
  удалялись. Контейнеров с префиксом `finspace-asb-e2e` не осталось.
- Удалены только временные каталоги `.tmp/asb-reliability-e2e` и
  `outputs/asb-reliability-e2e` внутри workspace.
- Production-сервер, production-база, пользовательские книги и секреты не
  изменялись.

Исторические audit/inbox/outbox записи изолированного dev-контура сохраняются в
соответствии с текущей моделью retention; публичного hard-delete для них нет.

## Вывод

Основной двусторонний путь, конфликтные решения, защитные проверки и повторная
доставка после DNS/HTTP 503 работают. Для технической истории binding остаётся
архитектурный вопрос о retention/admin cleanup: публичного hard-delete для audit,
inbox и outbox в текущей модели нет.
