# ADR 0002: PostgreSQL как финансовое ядро

- Статус: принято
- Дата: 2026-07-22

## Контекст

После foundation-этапа приложению нужны счета, категории, операции, аудит и строгие
расчёты. Данные должны быть изолированы по workspace, изменения — атомарны, а деньги не
должны проходить через float.

## Решение

Финансовая истина хранится в PostgreSQL и вводится миграцией `0002_financial_core`.
Используются UUID, `NUMERIC(20,4)`, timezone-aware timestamps, CHECK constraints, soft
delete, partial unique indexes и optimistic locking через `version`.

HTTP-слой отделён от доменных сервисов и явных repositories. Контекст определяется
централизованно по development-заголовкам. Изменение сущности и запись audit выполняются
одной DB-транзакцией. Остатки и summary рассчитываются из журнала операций Decimal-
арифметикой.

Frontend сохраняет деньги строками, применяет централизованный API client и использует
same-origin Next.js proxy. Bootstrap создаёт только фиксированные тестовые справочники.

## Последствия

- финансовые инварианты можно проверять транзакционно и независимо тестировать;
- downgrade полностью возвращает схему к `0001_foundation`;
- конфликт версий требует повторной загрузки клиентом;
- audit увеличивает объём БД, но даёт трассируемость;
- текущие development-заголовки нельзя считать авторизацией;
- Google Sheets и n8n должны подключаться позднее через API, не напрямую к БД.
