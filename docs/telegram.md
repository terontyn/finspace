# Telegram

Локальная интеграция использует long polling через n8n и не требует публичного webhook.
Telegram bot token хранится только как n8n credential. Backend доверяет не username, а
числовым `telegram_user_id` и `telegram_chat_id` активной привязки.

## Привязка

1. Откройте раздел **Telegram** и создайте одноразовый код.
2. За 10 минут отправьте боту `/link <код>`.
3. Backend сверит SHA-256 hash, workspace, срок, число попыток и отметит код
   использованным. Код нельзя применить повторно.
4. Статус и отзыв привязки доступны в том же разделе.

Username сохраняется только как вспомогательная метка. После отзыва команды, callbacks
и уведомления отклоняются.

## Команды и подтверждение

Поддерживаются детерминированные русские команды расхода, дохода и перевода. Сумма
разбирается через `Decimal`, разделитель может быть запятой или точкой. Backend ищет
точное соответствие активного счёта и категории в workspace; неоднозначность возвращает
`TELEGRAM_PARSE_AMBIGUOUS`, а не выбирает объект случайно.

Сообщение создаёт короткоживущий intent и preview. В callback передаётся только
непрозрачный короткий идентификатор и действие confirm/cancel. При confirm Backend ещё
раз проверяет Telegram ID/chat, срок и workspace и создаёт транзакцию обычным финансовым
сервисом. Cancel ничего не создаёт; повторный callback идемпотентен.

Для smoke-проверки после создания service account и credential:

```powershell
.\scripts\telegram-link-test.ps1 -AccessToken $token -WorkspaceId $workspace
```

Не помещайте в логи полный Telegram update, bot token, service key или полный текст
финансового сообщения. API и audit сохраняют только минимальные summaries.
