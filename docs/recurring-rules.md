# Регулярные операции

Правило хранится и проверяется Backend. n8n только запрашивает due rules и запускает
сохранённое правило; сумма, счета, категория и описание из workflow не принимаются как
источник истины.

## Расписание и режимы

Поддерживается валидируемое подмножество RRULE: `DAILY`, `WEEKLY`, `MONTHLY`, `YEARLY`,
а также `INTERVAL`, `BYDAY`, `BYMONTHDAY`, `BYMONTH`, `BYHOUR`, `BYMINUTE`, `UNTIL`.
Timezone должен быть IANA-именем. Форма UI создаёт распространённые дневные, недельные
и месячные правила без ручного ввода RRULE.

Режимы выполнения:

- `draft` — создаёт черновик, который editor/owner подтверждает через
  `POST /api/v1/transactions/{id}/confirm`;
- `confirmed` — создаёт подтверждённую транзакцию и transactional outbox;
- `reminder_only` — создаёт только историю/напоминание.

Backend проверяет положительную сумму, workspace и архивность счёта/категории, тип
категории, разные счета перевода и одинаковую валюту. По умолчанию UI предлагает
безопасный режим `draft`.

## Идемпотентность и история

На `(rule_id, scheduled_for)` действует уникальность. Запуск n8n также требует
`X-Idempotency-Key`, например `recurring:<rule_id>:<scheduled_for>`. Повтор возвращает
существующий execution и не создаёт вторую транзакцию или уведомление. Все create,
update, pause/resume и execute фиксируются в audit; история доступна в карточке правила.

```powershell
make recurring-test
```
